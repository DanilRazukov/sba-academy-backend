# Приём заявок с лендинга (Go)

Сервис принимает заявки с формы «Оставьте заявку» на academysba.pro и рассылает их менеджерам в **Telegram** и на **почту** (через SMTP или HTTP API Resend). Работает только на стандартной библиотеке Go. Письмо собирает соседний пакет [`appmail`](../appmail/README.md).

## API

### `POST /applications`

Тело запроса — контракт фронта из `src/shared/api/application.types.ts` в [репозитории лендинга](../README.md#связь-с-лендингом):

```json
{
  "fields":   { "courseId": "crypto-assets", "name": "Анна", "phone": "+7 900 123-45-67", "email": "anna@mail.ru" },
  "botCheck": { "trap": "", "fillTimeMs": 8500 }
}
```

| Ситуация | Статус | Ответ |
|---|---|---|
| Заявка доставлена хотя бы в один канал | 201 | `{"ok":true,"applicationId":"A-261028-3f9a1c"}` |
| Похоже на бота: ловушка заполнена или `fillTimeMs` < 3000 | 201 | то же, но заявку никуда не отправляем |
| Поля не прошли проверку | 422 | `{"ok":false,"code":"validation","fieldErrors":{"email":"…"}}` |
| Больше `RATE_LIMIT_MAX` заявок за окно с одного IP | 429 | `{"ok":false,"code":"rate-limited"}` и заголовок `Retry-After` |
| Битый JSON или тело больше 16 КБ | 400 / 413 | `{"ok":false,"code":"server"}` |
| Не сработал ни один канал | 502 | `{"ok":false,"code":"server"}` |

Проверки полей и тексты ошибок повторяют фронт: `src/features/submit-application/model/validate.ts` и `form-content.ts`. Менять их нужно вместе с фронтом.

Каналы работают параллельно, и клиент получает ответ **по первому успешному**: медленная почта не держит форму. Остальные каналы досылают заявку в фоне, а при остановке сервис их дожидается. Если какой-то канал сломался, это пишется в лог как `channel failed`. Если не сработал ни один, клиент получает 502, а в логе появляется `application lost`: такие заявки нужно поднимать руками.

### `GET /health`

Отвечает `{"status":"ok"}`. Подходит для проверки живости в Docker, Kubernetes и мониторинге.

## Настройка

Все настройки задаются переменными окружения, полный список с пояснениями — в [`.env.example`](.env.example). Обязательны `ALLOWED_ORIGINS` и хотя бы один канал. Если настройки неверные, сервис не стартует и перечисляет все проблемы сразу.

**Telegram**
1. Создайте бота у [@BotFather](https://t.me/BotFather) и возьмите у него токен.
2. Добавьте бота в чат менеджеров и напишите в чат любое сообщение.
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите в ответе `chat.id`. У групп он отрицательный.

**Почта через Resend** нужна там, где хостинг закрывает исходящий SMTP (так делает бесплатный Render).
1. Зарегистрируйтесь на [resend.com](https://resend.com) и создайте ключ в разделе «API Keys». Он пойдёт в `RESEND_API_KEY`.
2. **Стенд, без своего домена:** `RESEND_FROM` оставьте пустым, письма уйдут с `onboarding@resend.dev`. Resend разрешает так отправлять **только на email, с которым зарегистрирован аккаунт**, поэтому в `RESEND_TO` должен быть он. На другой адрес API ответит 403, и в логе появится `channel failed` с объяснением.
3. **Прод:** «Domains» → добавьте домен заказчика и пропишите в его DNS записи, которые покажет Resend (SPF, DKIM). После проверки задайте `RESEND_FROM=noreply@<домен>` и любых получателей в `RESEND_TO`.

**Почта через SMTP.** Для Яндекса: `smtp.yandex.ru`, порт 465, пароль приложения из настроек Яндекс ID. Для Gmail: `smtp.gmail.com`, порт 587, пароль приложения, для этого нужна двухфакторная авторизация. Письма уходят от имени «SBA Academy» с адреса из `SMTP_USERNAME`. Отдельной настройки отправителя нет: Gmail и Яндекс всё равно не дают отправлять с адреса, отличного от логина.

## Запуск

```bash
# локально (bash; в PowerShell задайте переменные через $env:NAME="…")
ALLOWED_ORIGINS=http://localhost:3000 TELEGRAM_BOT_TOKEN=… TELEGRAM_CHAT_ID=… go run .

# Docker: собирать из корня репозитория, потому что нужен соседний модуль appmail
docker build -f application-api/Dockerfile -t sba-application-api .
docker run --rm -p 8080:8080 --env-file application-api/.env sba-application-api
```

Проверка вручную:

```bash
curl -i -X POST localhost:8080/applications -H "Content-Type: application/json" \
  -d '{"fields":{"courseId":"crypto-assets","name":"Тест","phone":"+79001234567","email":"test@example.com"},"botCheck":{"trap":"","fillTimeMs":5000}}'
```

Сервис логирует JSON в stdout. Телефон и почту в лог не пишем, только номер заявки и программу: так меньше персональных данных разносится по логам.

## Деплой: на что обратить внимание

- **Один экземпляр.** Ограничение частоты живёт в памяти. При нескольких репликах счётчик у каждой свой, и тогда лимит нужно переносить в Redis.
- **За nginx** включите `TRUST_PROXY=true`, иначе все клиенты получат IP прокси и будут делить один лимит. Без прокси оставьте `false`.
- **Таймауты.** Каждый канал ограничен 15 секундами. Если клиент закрыл вкладку, заявка всё равно дойдёт. При остановке (`SIGTERM`, `docker stop`) сервис ждёт до 20 секунд, пока досылаются фоновые каналы, поэтому `docker stop` запускайте с `-t 25`.
- **Персональные данные (152-ФЗ).** Имя, телефон и почта — это ПДн. Для российских пользователей сервис лучше держать на сервере в РФ. Маршрут через Telegram и зарубежную почту стоит согласовать с заказчиком.
